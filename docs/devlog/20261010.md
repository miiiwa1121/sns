## YouTube 連携を管理画面へ（CLI の `youtube:auth` を廃止）
- Decision 014（運用は画面で完結）の残りの例外だった YouTube 連携を画面に移した。
- 仕組み:
  - アカウント画面の「YouTube と連携する」→ `/api/youtube/oauth/start`（state を httpOnly cookie に置く）→ Google の許可画面 → `/api/youtube/oauth/callback`（state を照合 → トークン取得 → 認証したチャンネルの確認・重複チェック → 保存）→ アカウント画面に結果を表示。
  - 既存の OAuth クライアントはデスクトップアプリ型で、`127.0.0.1` の任意のポート・パスに戻せる。Google Cloud 側の設定変更は不要。
  - トークンの保存先は従来どおり `.env.local`。`src/lib/envFile.ts` で書き換え、動いているサーバーの `process.env` にもすぐ反映する。
  - OAuth クライアントの ID・シークレットも「設定」画面から保存できるようにした（`.env.local` を手で編集しなくてよい）。シークレットは画面に出さない。
  - 処理は `src/lib/youtubeAuth.ts` にまとめ、`agent/youtube-auth.ts` と `package.json` の `youtube:auth` を削除した。投稿・計測のエラーメッセージも、コマンドではなく画面の操作を案内するようにした。
- 詰まった点: `request.url` は Next.js がホストを `localhost` に正規化するため、ブラウザで `127.0.0.1:3001` を開いていると戻り先が `localhost` になり、state の cookie が届かない。Host ヘッダーから origin を作るようにした（`browserOrigin`）。
- 確認: 開始時のリダイレクト先（scope・state・戻り先 `http://127.0.0.1:<port>/api/youtube/oauth/callback`）と cookie、state 不一致・キャンセル時の表示、設定画面の「設定済み」表示。投稿用クライアントから redirect URI を外した後も、既存のトークンで「ついていくのが精一杯」のチャンネルを取得できた。**Google の許可画面を通した実際の連携は未実施**（ユーザーが画面で試す）。
